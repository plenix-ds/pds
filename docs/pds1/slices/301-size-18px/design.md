# #301: retire `plx-ref.size-18px` (off the 4px grid): per-reader pick (G2)

- **What it is:** a defect inside the definitions (DESIGN.md §5: everything on the 4px grid). It's fixed without an owner question.
- **Option A** (the DS Architect's recommendation): move each reader to a grid size, then deprecate the token.

## Per reader

| Reader | Pick | Why |
|---|---|---|
| `plx-comp.data-grid-tree-indent` | **20px, `plx-ref.size-5u`** | One level = toggle (`data-grid-tree-control-size`, 14px) + gap (`data-grid-tree-control-gap`, 6px) = 20px. Each child's toggle then sits exactly under its parent's label. 16px would put it 4px inside the parent's toggle. |
| `data-grid.css` 495–497: the `18px` / `lead+18px` sticky steps and the `18px` table holder height step | **remove the step** (no replacement) | These rules are generated by `build-steps.js` from the size palette, as is `SIZE_STEPS`. Once 18px leaves the palette, the CSS step and the JS list lose it together. A measured value snaps to 16 or 20px, like any other value between steps. |
| `resizable.css` 36–37: the `18px` width and height steps | **remove the step** | Same generated ladder (`SIZE_STEPS`). |
| `docs/page-headers/plenix-page-headers.html:268` | **follows the palette** | It's the study's copy of the palette. Regenerate or delete the line, and don't keep 18px there. |

## Notes for the build (ds-architect)

- **The deprecated alias must not be generated:** if `size-18px` stays as a deprecated alias, `build-steps.js` must skip it, so the 18px steps don't come back.
- **Visible change:** tree rows in DataGrid indent 2px more per level (light and dark, every density; the indent isn't a density token). RTL: the indent is `padding-inline-start`, so it's mirrored already.
- **State matrix:** n/a. One token value changes and no state changes; the tree cell keeps its existing matrix.
- **Edge cases:**
  - 8 levels deep is 16px wider than today (fits; cells already truncate with ellipsis);
  - 10,000 rows: unchanged.
